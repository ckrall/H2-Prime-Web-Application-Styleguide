Do this first — the library has to be published

Everything below is applied to the library files but not yet published. Until the H2 Prime Variables Library is published, consuming files can't see the new variables, and until the shadcn-studio Library is published, Body/base won't appear in the working file. One consequence is already visible: Body/base's line height is a literal 28.8px rather than bound to line-height/body-base, because that variable didn't exist in the component library's import set at creation time. After publishing both libraries, rebind it.

A

Why these and not others

The v2 pass fixed nine defects in tokens.css, main.css and components.css. Most of them have no Figma counterpart at all, which is worth stating plainly so nobody goes looking for work that doesn't exist:

Which CSS defects map onto Figma work
CSS defectFigma impact
Dark-mode block was an invalid selector list, so dark mode never appliedNone. CSS syntax. Figma has native modes and was never affected.
Forty @theme entries referenced themselves, killing every radius, shadow, weight, leading and tracking utilityNone directly. Tailwind plumbing, never mirrored. But it caused the --h2p-* rename, which moved Code Syntax — see §C.
Semantic type roles declared in two placesNone. CSS classes. Figma has text styles.
White on success-500 at 3.30:1; every dark-mode on-solid still whiteVariables added — they didn't exist. See §B.
Placeholder, input border, secondary border, strong border below their thresholdsOne edit, three additions. See §B.
Theme layer had no dark counterpart; phase tokens had no dark valuesNone yet — neither is mirrored. Scope note for §13B and §10.
Three chart series below 3:1 on whiteNone — viz/* isn't mirrored, and shouldn't be until the palette is resolved. See §E.
The finding that mattered more than the fixes

The Semantic collection held 44 variables and simply did not contain most of the ones that failed. No text/on-*, no input/*, no text/placeholder, no interactive-secondary/*. That is not a gap in documentation — it is the mechanism by which the failures happened. With nothing to bind to, a designer filling a Success badge in Figma picks white by eye, and 2.28:1 ships.

Why the two scrims are raw values rather than aliases
Both carry alpha, and the primitive ramps are opaque. Aliasing would mean adding translucent primitives that exist for one consumer. The drawer scrim is deliberately lighter than the modal scrim — 0.45 against 0.60 — because keeping the page behind legible is what tells a user a panel is a layer and not a new screen. That is Section 14's whole argument, encoded in a token.
One deliberate non-addition
text/on-primary was not created. interactive-primary/text already exists and resolves identically, and two names for one decision is how a collection starts to rot.
C

Code Syntax — 19 repointed

v2 moved every raw scale that collided with a Tailwind v4 namespace to an --h2p-* canonical name. The unprefixed names survive as deprecated aliases, so nothing breaks — but Code Syntax should hand a developer the canonical name, not the one scheduled for removal.

tracking/tight    var(--tracking-tight)   →  var(--h2p-tracking-tight)
tracking/normal · wide · wider · widest                    (5 total)

leading/tight     var(--leading-tight)    →  var(--h2p-leading-tight)
leading/snug · normal · relaxed · loose                    (5 total)

radius/none       var(--radius-none)      →  var(--h2p-radius-none)
radius/xs · sm · md · lg · xl · 2xl · 3xl · full           (9 total)

Colour and spacing variables were untouched. --text-secondary and --space-4 don't sit inside a Tailwind namespace, so they keep their names and their Code Syntax is still correct.

The rule that keeps this from recurring
Never map a Tailwind namespace name onto a tokens.css variable of the same name. The namespaces are --color-*, --font-*, --font-weight-*, --text-*, --leading-*, --tracking-*, --spacing-*, --radius-*, --shadow-*, --z-index-*. Anything landing in one of those carries the --h2p- prefix at its source. The rule is restated in the main.css header.
D

Typography — the 18px gap

This was not on the list going in. It surfaced from reading the library rather than from the token diff, and it is the most consequential thing in this amendment.

Figma had no style at the product's base body size

The product's base is 18px — the decision the entire audience rationale rests on, and the reason the scale departs from Tailwind's 16px stock. The library's twelve H2 Prime text styles included no 18px Inter Regular. Body/p, the obvious reach for running text, is 16px and maps to --type-body-sm, not --type-body.

So every Figma screen composed with Body/p has been a size off from the shipped app, in the one dimension the audience research was most specific about.

Body/p was kept rather than rebound. Changing its size from 16 to 18 would reflow every existing use across the library and the working file — a migration, not a fix, and one that deserves its own pass. Instead all three ambiguous styles now carry descriptions:

A text style that didn't need creating

tokens.css v2 introduced --type-overlay-title-* for drawer and sheet headings. Reading the library showed Heading/H3 is already Inter Semi Bold 22 / 28.6 — identical. So there is no thirteenth heading style; the overlay title is a role alias.

That fed a correction back into CSS: the first draft of tokens.css v2 restated H3's values under the overlay-title name instead of aliasing them, which would have let the two drift apart silently. It now aliases --type-h3-* the way every other component-scoped role in §2.19 does.

E

Left alone, with evidence

Each of these was checked rather than assumed, and each is a decision rather than an oversight.

Items deliberately not changed
ItemWhat was checkedWhy it was left
font-size/5xl OPEN Resolved every text style's bindings. Nothing binds to it. It duplicates font-size/4xl at 40px. Safe to delete, but a deletion in a shared library is the owner's call, not a sync task.
tracking/* unit bug OPEN Only tracking/display is bound to any style, and it is correctly stored as -0.2px. The five scale variables hold em fractions Figma would read as pixels. Latent, not active. Fix the five before binding them to anything, not after — binding first would make a silent 18× error visible everywhere at once.
Radius / spacing duplication OPEN Both groups exist inside H2 Prime Primitives and in their own dedicated collections. The rebind plugin orders around it deliberately. Resolving it means a rebind pass of its own.
viz/* not mirrored OPEN No viz group exists in Primitives or Semantic. Three of eight series changed in v2, and the palette collapses under deuteranopia. Resolve the palette, then mirror — mirroring a set that's about to change is worse than not mirroring it.
No elevation effect styles OPEN §13A-E says shadows ship as Effect Styles. The component library has shadcn-studio's own scale; no H2 Prime set exists. Shadow values didn't change in v2, so nothing is wrong today. It's a documentation/reality mismatch in 13A, now flagged there.
Theme and phase dark variants Neither is mirrored at all. §13B is blocked on §11, and the phase scheme belongs to §10. The v2 values exist in CSS; Figma follows when those sections land.
Overlay geometry and durations No Overlay collection exists. Worth creating alongside the Section 14 component build rather than speculatively. Easing can't be a Figma variable at all.

One false alarm worth recording
The first verification pass reported 18 unresolved pairings and looked alarming. The cause was in the checking script, not the data: it followed aliases into the Primitives collection while still passing the Semantic collection's mode id, which doesn't exist there, so every alias returned undefined. An alias has to be resolved against its own collection's modes. Worth knowing for anyone writing a similar audit — the failure mode looks exactly like broken variables.
