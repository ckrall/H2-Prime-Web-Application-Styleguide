H2 Prime Web Application Design System & Guidelines

Section 05 — Component Patterns

Reference markup and token usage for the components that appear across every H2 Prime screen. Every example uses real semantic HTML5 — no <div> or <span> standing in for an element with a native equivalent — and every color reference is a token from Sections 2 and 4, never a hardcoded hex value. Section 10 (Contract Phase System) and the per-dashboard theme treatments (Client / Filer / Admin, Section 11) are intentionally not covered here — both are parked pending a dedicated review pass.

5A

Buttons

Primary uses the Neutral ramp, not Brand Yellow or Brown — see §2D-2 for why. At most one primary button per view; everything else is secondary or ghost.

Live — dark shell
<button type="submit" class="btn-primary">Submit contract</button>
<button type="button" class="btn-secondary">Save draft</button>
<button type="button" class="btn-ghost">Cancel</button>
<button type="button" class="btn-danger">Terminate contract</button>
VariantBackgroundTextUse
Primary--interactive-primary-bg (neutral-800 LM / neutral-100 DM)#FFFFFF LM / neutral-950 DMOne per view — the single most important action
Secondarytransparent, neutral-300 border--text-primaryAny other meaningful action alongside primary
Ghosttransparent--text-secondaryLow-emphasis actions — Cancel, Skip
Danger--ramp-danger-500#FFFFFFDestructive/irreversible actions only — always paired with a confirm step
Where Brown and Yellow do show up
Not on the button itself. Use Brown in the header band above a button group or in an icon accent next to the primary action; use Yellow for a focus ring or an active-tab indicator. This is how brand identity stays visible on a screen whose CTA is Neutral.
5B

Form fields

Every input has a linked <label> — never a placeholder standing in for a label. Error and hint text are linked via aria-describedby, and invalid fields carry aria-invalid="true".

Live — dark shell
As it appears on your H-2A application
Enter a valid email address 
<div class="field">
  <label for="business-name">Farm or business name</label>
  <input type="text" id="business-name" name="business_name"
         autocomplete="organization" aria-describedby="business-name-hint">
  <span class="hint" id="business-name-hint">As it appears on your H-2A application</span>
</div>

<div class="field">
  <label for="contact-email">Contact email</label>
  <input type="email" id="contact-email" name="email"
         aria-invalid="true" aria-describedby="contact-email-err">
  <span class="err" id="contact-email-err" role="alert">Enter a valid email address</span>
</div>
Don't use placeholder as label

Placeholder text disappears the moment someone starts typing — a real problem mid-form on a small phone screen in bright sunlight, which is a common H2 Prime use case.

Do keep the label always visible

A visible <label> above the field costs a little vertical space and buys back a lot of certainty for a non-technical, often distracted user.

5C

Grouped form fields

Any set of related inputs — especially radio/checkbox groups — uses <fieldset> and <legend> so assistive technology announces the group's purpose before its options.

Live — dark shell
Notification preferences 
<fieldset>
  <legend>Notification preferences</legend>
  <div class="field field-check">
    <input type="checkbox" id="notif-email" name="notif" checked>
    <label for="notif-email">Email me when a contract changes phase</label>
  </div>
  <div class="field field-check">
    <input type="checkbox" id="notif-sms" name="notif">
    <label for="notif-sms">Text me for urgent deadlines only</label>
  </div>
</fieldset>
5D

Badges & status pills

Status pills always pair color with a text label — never color alone (WCAG 1.4.1). Rendered as <span> since a pill is inline decoration around text, not a distinct semantic element — but the text itself always says the actual state in words.

Live — dark shell
Expired Pending review Approved In progress Needs assistance Draft 
<span class="pill pill-warning">
  <svg class="icon" aria-hidden="true">…</svg>
  Pending review
</span>
5E

Cards

A card is an <article> when it represents one self-contained, independently distributable item (a single contract summary that could stand alone in a feed) and a <section> with a heading when it's one region of a larger composed page.

Live — dark shell

Rivera Farms — H-2A 2026

14 workers · Negotiation phase · Updated 2 days ago

In progress 
<article class="contract-card">
  <h3>Rivera Farms — H-2A 2026</h3>
  <p>14 workers · Negotiation phase · Updated 2 days ago</p>
  <span class="pill pill-info">In progress</span>
</article>

5F

Data tables

Every data table gets a <caption> (visually hidden if the surrounding heading already states the purpose) and scope on header cells, so a screen reader can announce which column a cell belongs to when navigating cell-by-cell.

Active contracts and their current phase
Contract Workers Phase Updated
Rivera Farms 14 Negotiation 2 days ago
Coastal Growers 22 Pending review 5 hours ago 
<table>
  <caption class="sr-only">Active contracts and their current phase</caption>

    <tr>
      <th scope="col">Contract</th>
      <th scope="col">Workers</th>

    <tr>
      <th scope="row">Rivera Farms</th>
      <td>14</td>

  </tbody>
</table>
5G

Feedback banners

Danger and Warning banners carry role="alert" so assistive technology announces them immediately on appearance. Success, Info, and Help banners use role="status" — important, but not urgent enough to interrupt.

Live — dark shell
⛔
Contract expired
This contract's end date has passed. Renew or close it out.
⚠️
Deadline in 3 days
Review is due before the negotiation window closes.
✅
Contract approved
Both parties have signed. Moving to Review.
<div class="banner banner-warning" role="alert">
  <svg class="banner-icon" aria-hidden="true">…</svg>
  <div>
    <p class="banner-title">Deadline in 3 days</p>
    <p class="banner-body">Review is due before the negotiation window closes.</p>
  </div>
</div>
5H

Icon-only controls

Any control whose only visible content is an icon must carry aria-label describing the action — the icon's shape alone conveys nothing to a screen reader.

Live — dark shell
<button type="button" aria-label="Delete contract">
  <svg class="icon" aria-hidden="true">…</svg>
</button>
Never rely on a tooltip alone
A hover tooltip is not a substitute for aria-label — it's invisible to screen readers and unreachable on touch devices, both of which matter for H2 Prime's mixed desktop/mobile, indoor/outdoor audience.
5I

Anti-patterns

Don't reach for Brown or Yellow on a button

Both are identity colors as of 2026-07-13. A Brown or Yellow button fill contradicts the primary-action decision in §2D-2 — flag it for a token swap to --interactive-primary-bg, don't hand-style around it.

Do reach for Neutral, every time, for CTAs

If a screen feels like it's "missing the brand," fix it with a Brown header band or a Yellow accent detail nearby — not by recoloring the button.

Don't build a clickable <div>

A <div onclick> gets no keyboard focus, no Enter/Space activation, and no role announcement for free — all of which a real <button> or <a> gives you automatically.

Do use the native element for the job

<button> for actions that happen on the current page, <a href> for navigation to a new location — including in-app route changes.
