B

Why the page is a table and the drawer is not

The two surfaces answer different questions, so they are not the same list at two widths.

Drawer — triage

You are on your way to something else and not leaving the page, so each notification is a card: icon, title, two lines of body, a context badge. It optimises for reading one item and deciding whether to act.

Page — volume

A filer with 127 unread is not reading; they are scanning for a pattern and then acting on several things at once. So it is a table with scannable columns and no body copy, plus search, full-history filters and multi-select bulk actions.

This is also what makes undo honest. The drawer can delete, but the 30-day recovery bin lives on the page — the Deleted option in the Status filter — so a deletion is never gone from the one surface that could get it back.

C

What it is made of

C.1

Two new local components

The shadcn library has no list-row primitive, so the row is the one thing that had to be built. It is a real component with properties, not a drawn group — which is what makes the volume differences between roles cheap to maintain.

H2P/Notification Row
Unread marker, type-icon tile, title, two-line clamped body, context badge, timestamp, row menu. Properties: Title, Body, Time (text); Unread, Show context badge, Show row menu (boolean); Type icon (instance swap). Fills the drawer width, hugs height.
H2P/Notification Group Header
The NEW / EARLIER date-group label with a count. Properties: Label, Count.
C.2

Library components used as-is

Everything else is an instance from H2 Prime shadcn-studio Library: Sheet (Type=Right) as the drawer shell, Tabs for Blocks and Tab item for the filter tabs, Separator, Soft Badge, Ghost Icon Button, Link Button, Outline Button, Solid Button, Skeleton, Dropdown, Check Box, Default Select, Default Input, Pagination, Breadcrumbs, and the Lucide icon components.

Colour, radius and type come from H2 Prime Variables Library and the shared text styles. No hardcoded hex values were introduced. The one exception is the full page's table grid, which is hand-built: the library's table-cell is a fixed 192px and Figma does not allow an instance sub-layer to be resized.

D

Six things the build turned up

Four are defects or gaps in the system rather than in this feature. They are ordered by reach, not by when they were found.

1 · The library Soft Badge fails AA and breaks in dark mode

A live defect reaching every badge in the product, not just this feature. Soft Badge paints its pill with two fills: a base bound to a surface token, and an opacity/*/60 tint on top. The base adapts to dark mode and the tint does not — it stays a light neutral in both modes. So in dark the pill stays pale while the label flips to near-white.

Soft Badge contrast as shipped, measured from resolved fills
BadgeComposited pillLabelRatioAA 4.5:1

The badge carrying the most urgent meaning in the system — Action needed — was the least legible of the set. Note also that Soft Badge never used H2 Prime's feedback tokens at all; it uses the shadcn library's own neutrals and tints, so the feedback-token contrast verified in §E was not what the badges were rendering.

Fixed in the build; still open in the library

All 92 badge instances across the drawer, the states section and the full page, in both modes, were rebound to feedback-*/surface and feedback-*/text — one fill, no opacity tint. Re-measured afterwards: 22 distinct pairings, zero failures, worst case 6.84:1, most clearing AAA. The same change belongs in the component, or every future screen reintroduces the defect.

2 · Neither border token reaches 3:1 in light mode

The separators are what give the drawer's list its structure. Measured against surface/raised:

Border token contrast against surface/raised
TokenLightDarkVerdict
border/default #D6D9DE1.42:12.46:1Effectively invisible in light
border/strong #959AA12.83:13.70:1Usable; just short in light

All 46 separators in the build were repointed to border/strong — double the light-mode contrast of where they started. Row separators are decorative rather than UI-component boundaries, so SC 1.4.11 does not formally bind, but a 1.42:1 line is not doing the job it was put there to do.

One-line fix available

Darkening light-mode border/strong from #959AA1 to about #8E939A takes it to 3.28:1 and clears the non-text threshold outright. The token is already nearly there, and it would let the system claim 3:1 on structural borders in both modes.

3 · The library runs on Geist; H2 Prime's own styles run on Inter

Every Tailwind/* text style in the shadcn library resolves to Geist. The H2 Prime Heading/* and Body/* styles resolve to Inter. Both are in use in this build — library component internals are Geist, the row text is Geist via Tailwind/SM/*, and anything using an H2 Prime heading style is Inter.

This is a real fork in the type system and it is recorded nowhere else. It needs a decision before the Notification Center ships: either H2 Prime adopts Geist and the Inter styles are retired, or the library's Tailwind styles are rebound to Inter. Mixing them is the one option that should not survive.

4 · The drawer's close button is 16 × 16

The Sheet component's close affordance is a 16px icon button. WCAG 2.2 SC 2.5.8 (Target Size, Minimum, AA) wants 24 × 24. It cannot be resized from an instance, so this is a library fix, not a screen fix. Everything else in the drawer clears it: the row menu buttons are 24, the bell trigger is 32, and the footer button is 32 tall and full width.

5 · The drawer is 524px wide, not the 420 in Section 14

Section 14 specified a 420px drawer. The library Sheet is 524px, and Figma does not permit size overrides on instance sub-layers — maxWidth returns “This property cannot be overridden in an instance”. So the choice was a 524px drawer built from the real component, or a 420px drawer that is a detached copy and stops tracking the library.

Built at 524. Inheriting the library's geometry is the point of using the component, and 524 is comfortable for a two-line body at 14px. Section 14 has been amended to 524 rather than the Figma file being bent to match the doc. If 420 is genuinely wanted, that is a change to the Sheet component, not an override here.

6 · Two token families the style guide assumes are not in Figma

Searching H2 Prime Variables Library returns nothing for theme/* or for any scrim or overlay token. The per-role accent (Client yellow, Filer sky, Admin violet) and the overlay scrims exist in tokens.css but have no Figma counterpart, so the drawer's scrim is currently inherited from the shadcn library's own overlay variable rather than from an H2 Prime token. This is the same gap Section 13A flagged for theme highlights, now reaching a second surface.

F

Carried over from Section 14, and what is still missing

F.1

Rules applied, not re-argued

The build is an application of the overlay rules. Four show up directly:

Section 14 rules as applied in this build
RuleHow it lands here
Drawer, not modalThe dashboard underneath is still the user's place — a glance on the way to something else — so the page recedes behind a translucent scrim instead of being replaced. The drawer is non-modal: it does not make the page inert.
ADR 14-1 — the trace ruleThe navbar bell carries an active surface and border alongside its unread dot in all six frames, so the open drawer is anchored to a specific control rather than floating free. The trigger is 32 × 32, clearing SC 2.5.8.
The destructive confirm is a modalDeleting is the one action in the drawer not reversible by the drawer itself, so it gets a surface that takes over; the undo lives in a toast afterwards. The row menu, which is reversible, stays in place.
ADR 14-2 — mobile keeps the peekThe sheet stops 56px short of the top and the scrim stays translucent, so the page underneath reads as a place you are still in. That was the load-bearing cue in the overlay prototype's mobile test — the other three cues cannot save it once it is gone.
F.2

Not done yet

Still missing from the Figma build

The three detail types — specified and wireframed in HTML, but not built in Figma.

Row hover, focus and selected states as a state set.

Table column sorting: the headers imply it, no sorted state is drawn.

The page's own empty and loading states — only the drawer's exist.

Notification preferences, the surface the empty state points at, is unscoped.

Blocking the system, not this feature

Both libraries still need publishing before the new variables and text styles reach other files.

Soft Badge, border/strong, the Geist/Inter fork and the Sheet close button are all library-side fixes — see §D.

theme/* and scrim tokens are still absent from the Variables Library.
