H2 Prime Web Application Design System & Guidelines

Section 13A — Figma Variable Reference — Global Tokens

How the mode-independent parts of tokens.css — primitive ramps, light/dark semantics, typography, spacing, radius, and elevation — are mirrored into Figma variable collections, and how each variable's Code Syntax field is kept pointed at the matching CSS custom property so a Figma value and its shipped code can't silently drift apart. This section is numbered 13A rather than 13 because it's a deliberate split: it covers only tokens that don't depend on the still-unresolved dashboard theme decision. The theme-dependent half is Section 13B, once Section 11 lands — see §13A-A.

The tokens.css v2 correctness pass changed eleven semantic values and renamed every raw scale that collided with a Tailwind namespace. The Figma library has been updated to match, and the full record — what changed, what was added, what was deliberately left alone and why — is in the 13A amendment.

Two things in this section were already stale before that pass and are corrected in the amendment rather than rewritten here:

  • There is no Layout collection. §13A-B describes one holding space/* and radius/*. It was created and then deliberately deleted in favour of separate H2 Prime Spacing, H2 Prime Radius and H2 Prime Border Width collections. Six collections are live, not four.
  • Role aliases were never mirrored. §13A-F cites radius/card and tracking/h1 as examples. Neither exists — the Radius collection holds the nine scale stops only, and Typography holds tracking/display plus the five scale steps.

13A-A

Scope — 13A vs. 13B

Section 13 was originally scoped as one pass covering "light mode, dark mode, and per-dashboard theme variables," and parked entirely because the dashboard theme review (§11) hadn't happened. That blocked more than it needed to: the global token layer — primitives, light/dark semantics, type, spacing, radius, elevation — is already locked and hasn't changed since the Neutral/Brown revision. Only the dashboard theme accent layer (§4 in tokens.css) is genuinely unresolved. So the section splits in two:

13A — Starts now
Global tokens
Every primitive ramp, both semantic modes, typography, spacing, radius, and elevation. Nothing here depends on how Client/Filer/Admin themes resolve — the reverse is true, per §13A-B.
→
13B — Blocked on §11
Dashboard theme variables
--theme-accent-*, themed navigation (--nav-*), and the still-unresolved "select a color set" picker. Consumes 13A's Primitives collection by reference once the per-dashboard identity treatment is decided.
Why this split is safe
Every --theme-accent-* value in tokens.css §4 is an alias onto a primitive ramp already defined in §1 (Yellow, Sky Blue, Violet). The primitive ramps themselves aren't in question — Sky Blue and Violet are already fully specified 12-step ramps, they're just not yet assigned to a settled role. 13A mirrors the ramps as-is; 13B only has to decide which alias points where and add that thin mapping layer on top. Nothing built in 13A gets thrown away when §11 resolves.
A third thing that's also out of scope here
Contract Phase colors (tokens.css §1.11 primitives, §2.13 semantic aliases) are not part of either 13A or 13B — they're tied to Section 10 (Contract Phase System), which predates the Brown/Neutral revision and hasn't been revalidated. They'll get their own pass once §10 resolves, most likely alongside 13B rather than a separate 13C, but that's not decided yet. NOTE The v2 pass added dark-mode phase values to tokens.css because their absence was a straight bug — a phase chip rendered near-white on a near-black page. The phase scheme is still §10's to settle, and none of it is mirrored into Figma.
13A-B

Variable architecture

Figma's Collections + Modes model maps onto the existing CSS three-tier system directly enough that no new mental model is needed — a Figma collection is a tier, and a Figma mode is what [data-mode] already does in CSS.

H2 Prime Primitives
1 mode · 172 variables
Mirrors tokens.css §1. Every ramp, every step, raw color values. Never bound directly to a layer fill in product screens — only referenced by the Semantic collection.
H2 Prime Semantic
2 modes — Light, Dark · 55 variables
Mirrors tokens.css §2–§3. Every variable aliases a Primitives variable; the alias target changes per mode, exactly like the [data-mode="dark"] override block.
H2 Prime Typography
1 mode · 49 variables
tracking/*, leading/*, font-size/*, font-weight/*, font-family/* and per-role line-height/* as number and string variables, referenced inside Figma Text Styles rather than driving type directly — see §13A-E.
H2 Prime Spacing
1 mode · 16 variables
The 4px grid. Binds directly to auto-layout gap and padding.
H2 Prime Radius
1 mode · 9 variables
The nine scale stops. Role aliases (--h2p-radius-btn, -card, -dialog, -sheet) are CSS-only and deliberately not mirrored.
H2 Prime Border Width
1 mode · 5 variables
Mirrors Tailwind's border-width scale.
H2 Prime Theme13B
3 modes — Client, Filer, Admin
Not created yet. Will alias into Primitives once §11 resolves which ramp each dashboard's accent, nav, and interactive-secondary treatment actually uses.
H2 Prime Overlay§14
1 mode
Not created yet. Drawer and modal widths, sheet peek, grabber dimensions and durations from tokens.css §2.21–§2.22. The two overlay scrims live in Semantic instead, since they're colours with mode values. Easing cannot be a Figma variable at all.

Every Figma variable name uses forward slashes as the Figma-native group separator, mapped one-to-one from the CSS token's hyphenated segments — --ramp-neutral-700 becomes neutral/700 inside the Primitives collection, --text-secondary becomes text/secondary inside Semantic. This keeps the segment order from §8C intact; only the delimiter changes.

Radius and spacing exist twice
Both groups appear inside H2 Prime Primitives and in their own dedicated collections. The rebind plugin orders around this deliberately — Primitives is processed first so the dedicated collections win — but it is still two sources for one value, and it should be resolved rather than worked around indefinitely.

interactive-primary/bg is a real exception, not a mapping error
Most Semantic variables mirror the same ramp step in both modes with the "which end is light/dark" logic flipped. interactive-primary/bg doesn't — it's Neutral-800 in Light and Neutral-100 in Dark, both near-opposite ends deliberately, so the fill never goes muddy or vanishes into the dark canvas. Anyone editing this variable in Figma should see both alias targets and not "correct" the dark value to Neutral-900 by pattern-matching the rest of the collection.
Why the on-solid set had to be added
text/on-danger through text/on-help did not exist before the v2 pass, which meant a filled Success badge in Figma got its white text picked by hand. White on success/400 measures 2.28:1. The variables now carry the measurement in their description, so the right value is the default rather than something a designer has to know.
13A-E

Typography & layout collections

Not every token in tokens.css §2.14–§2.22 maps to a Figma variable cleanly — Figma variables cover color, number, string, and boolean, but a full type role (family + weight + size + line-height together) is better represented as a Figma Text Style that references number variables, not as one variable itself.

13A-F

Code Syntax binding

Every Figma variable in scope gets its Code Syntax field (Web platform) set to the exact CSS custom property it mirrors. This is what keeps a Figma value and its shipped CSS from drifting silently apart — the binding is machine-checkable, not just a naming convention someone has to remember.

// Figma variable: color/neutral/700  (Primitives)
// Code Syntax → Web: --ramp-neutral-700

// Figma variable: text/secondary  (Semantic, Light mode)
// Code Syntax → Web: --text-secondary
// Value: alias → color/neutral/700
The v2 rename, and what it means for Code Syntax

tokens.css v2 moved every raw scale that collided with a Tailwind v4 namespace to an --h2p-* canonical name — radius, shadow, leading, tracking, font-weight and the font families. The old names survive as deprecated aliases, so nothing breaks, but Code Syntax should hand a developer the canonical name rather than the one scheduled for removal.

Nineteen variables were repointed in the 2026-10-25 pass: five tracking/*, five leading/* and all nine radius/*. Colour and spacing variables were unaffected — --text-secondary and --space-4 don't sit in a Tailwind namespace and keep their names.

Do treat a Code Syntax mismatch as a bug report
If a Figma variable's Code Syntax field and its actual behavior in the shipped app disagree, that's a signal one side is stale and should get fixed at the source — usually tokens.css, since it's authoritative — rather than quietly edited in Figma to match what the screen currently looks like.
13A-G

Gaps & open decisions

The tracking variables carry a latent unit bug

Figma resolves a FLOAT bound to letterSpacing as raw pixels, whatever unit was intended. The five tracking/* scale variables store CSS em fractions — tracking/tight is -0.025, meaning -0.025em, which Figma would apply as -0.025px. At the 18px base that should be -0.45px, so the tracking would be roughly eighteen times too small.

It is latent, not active. Only tracking/display is currently bound to a text style, and that one is correctly stored as -0.2px — the pixel equivalent at 40px, set deliberately. Fix the other five before binding them to anything, not after.

Not mirrored, and should be

--viz-* chart series. Three of the eight changed in the v2 pass for contrast, and the palette collapses under deuteranopia — see tokens.css §2.12. Worth resolving the palette before mirroring it, rather than mirroring a set that's about to change.

No H2 Prime effect style set for elevation. §13A-E says shadows ship as Effect Styles; none exist, so component shadows come from shadcn-studio's own scale.

Ready to build on

Primitives, Semantic, Typography, Spacing, Radius and Border Width all have no open dependencies. A designer can bind component variants to these today without waiting on §10 or §11.

Deliberately deferred

Theme collection (13B), Contract Phase, themed Navigation. Don't create placeholder Figma variables for these ahead of time; an empty or guessed alias is worse than an absent one, since it looks decided when it isn't.

Worth deciding next

Whether to delete font-size/5xl — it duplicates font-size/4xl at 40px and nothing binds to it. Whether to resolve the radius/spacing duplication between Primitives and the dedicated collections. And whether Contract Phase folds into 13B or becomes 13C.
