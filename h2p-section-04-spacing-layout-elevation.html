4B

Spacing usage rules

Three fixed padding tiers cover nearly every container in the product. Pick by density, not by eyeballing a number.

Container padding tiers Pick one per container type — don't mix within a single component
Compact (--space-3, 12px) — table cells, dense list rows, filer dashboard density mode.
Comfortable (--space-4, 16px) — default card and panel padding, the baseline for most of the app.
Spacious (--space-5 to --space-6, 20–24px) — top-level page cards, modal bodies, anything meant to feel like the primary focus of the screen.
Don't hand-pick pixel values

A component with padding: 14px or margin-top: 18px is off-grid — it won't line up with anything else on the page, and it's a value nobody else can reuse with intent.

Do compose from the scale

Every gap should be a named stop: p-4, gap-2, space-y-6. If nothing on the scale looks right, that's a signal to flag a gap here rather than reach for an arbitrary value — see §4H.

4C

Page layout & breakpoints

H2 Prime doesn't currently define custom breakpoints in main.css — Tailwind v4's defaults apply unmodified. Documented here so the absence is a decision, not an oversight.

BreakpointMin widthPrimary use in H2 Prime
sm640pxLarge phones landscape — form fields go from stacked to inline
md768pxTablet — sidebar nav becomes visible instead of a drawer
lg1024pxSmall laptop — the primary desktop breakpoint for this app
xl1280pxDesktop — content max-width caps out, extra space becomes margin
2xl1536pxWide desktop — rarely targeted directly
Mobile-first, deliberately
Given the audience (frequent outdoor/field use on phones — reviewing a contract at a job site, not just at a desk), build every screen for the smallest viewport first and add complexity at lg and up, not the reverse. A layout that only works with a sidebar and a wide table is a layout that fails a farmer standing in a field.

Single-sided borders
A left- or top-accent border (used on some callout and status-card patterns — see Section 5) must use border-radius: 0. Rounding a corner that only has a border on one side produces a visible seam where the rounded corner meets a square one.

4E-1Light vs dark mode shadow values

Light mode shadows use a low-opacity near-black (rgba(28,27,30,…), 4–10% alpha). Dark mode raises opacity to 25–45% at the same blur/spread — without this, a shadow computed for a white page becomes invisible on a near-black one. Only opacity changes between modes; blur and spread stay fixed per stop.

4H

Anti-patterns

Don't invent a new shadow for "just this one card"

If none of the six stops feel deep enough, that's a cue the component's actual elevation role is unclear — pick the nearest role (card, dropdown, modal) rather than hand-tuning blur and spread.

Do treat radius as a role, not a size choice

--radius-card should be used because something is a card, not because 8px looked good. Swapping the card radius later should be a one-line token change, not a find-and-replace across component files.

Don't stack more than two floating elevations

A dropdown opened from inside a modal is fine. A tooltip on a dropdown opened from inside a modal starts to feel structurally unstable, especially on a small mobile viewport — collapse to a simpler pattern instead.

Do flag gaps here instead of improvising

This is a start version, consistent with Sections 2 and 3. If a real screen needs a spacing value, radius, or elevation role that doesn't exist yet, add it to tokens.css and this page together.
